# 既有服务器运行配置

公开客户端通过 SSH 调用使用者已有权限的服务，只上传冻结请求并下载结果。
服务器的计算引擎、部署流程、执行入口和数据适配由服务维护者管理，
不包含在公开客户端源码或安装包中。安装客户端不会安装或升级服务器。

以下为 CLI 源码 `0.2.0` 的行为；最新正式客户端仍为 `0.1.1`，
不能据此认为 `0.2.0` 已正式发布或服务器已完成配套更新。

## 默认配置与自定义路径

首次 `fe-cli init` 会在 workspace 创建 `runtime.json`，使用以下标准配置：

| 配置 | 默认值 |
| --- | --- |
| 服务器解释器 | `/public/fe-core-env/bin/python` |
| Core 入口目录 | `/public/fe-core` |
| 数据目录 | `/srv/quant/data/shared/ashare_lqtp_data` |
| 节点 / 环境 / 时限 | `quant-a` / `research` / `00:30:00` |
| 清单摘要 | `null`，选择作业启动时的当前 Core |

初始化完全在本机进行，不连接服务器，不验证路径或授予数据权限。
重复初始化保留已有有效运行配置；损坏配置报错并保留。
标准路径适用时，无须再填写运行参数；也可执行 `fe-cli configure-run` 显式保存标准默认值。
自定义路径须使用维护者确认、使用者获准访问的值：

```bash
fe-cli configure-run \
  --remote-python "$REMOTE_FE_PYTHON" \
  --data-root "$DATA_ROOT" \
  --release-root "$RELEASE_ROOT"
```

路径参数均可省略，省略时采用上表的标准值；`configure-run` 不从旧配置继承省略项。
保存本身不连接服务器，也不证明路径存在、权限有效或版本兼容。
不填写 `--release-sha256` 时使用当前 Core；需要高级固定模式时，
可额外传入 `--release-sha256 "$RELEASE_SHA256"` 保存维护者提供的具体清单摘要。
默认节点约束为 `quant-a`；需要 C 节点时显式传入 `--node C`。
若维护者确认该版本可跨节点使用，可额外指定 `--node shared`。

## 请求和服务身份

每个新任务冻结请求、入口目录和运行模式，上传包只含 `request.json`。
默认模式在冻结请求中保留 `release_sha256: null`，调用既有 runner 时使用
`--release-sha256 current`；服务器必须支持这一参数，在作业启动时校验实际 Core 与清单，
将真实清单摘要、Core 提交和 wheel 身份记录到结果的 `engine`，不修改原请求。
客户端对当前模式结果要求 `engine.release_sha256`、`engine.engine_commit` 和
`engine.core_wheel`（文件名、字节数和 SHA256），缺失时拒绝本机交付。
固定模式继续严格使用请求内的指定摘要，不自动转成当前模式。
客户端通过获授权的 SSH 提交入口把请求交给既有服务；认证、任务状态、
结果下载和本机交付分别记录。SSH 使用严格主机校验，不读取私钥正文或保存密码。

客户端请求/结果协议为 `fe-cli-result-v1`，既有服务清单协议为
`fe-cli-public-release-v1`。产品版本号不代替协议与能力兼容检查。
当前模式按作业启动时的服务器版本解析，可能与准备请求时不同；
本机旧请求和结果继续保留原身份，不自动改写。

在线终端 `/status` 或普通命令 `fe-cli --online status` 检查 SSH authorization status，
只建立 SSH 握手并检查公钥认证，不执行远程命令或查询环境；严格主机校验保持开启。
`/setup` 和普通命令 `setup` 保留兼容别名，菜单和帮助以 `status` 为主。
demo 模式只显示本机状态，SSH 认证成功也不代表 Core、数据或计算权限已经验收。

### 固定目录的服务更新

维护者也可明确选择固定源码目录与固定环境目录，后续在原位置更新，避免逐版本累积整套环境。
固定路径仍须配合每次部署的 Core 提交、安装包身份和新的清单摘要，不能只凭目录名确认版本。
更新前暂停提交，确认没有运行中或排队中的任务引用这两个目录；环境应在最终路径创建，
以后复用现有环境更新依赖，不直接搬移环境或在作业运行期间覆盖包。

更新完成并验收后，只要路径和接口保持兼容，当前模式用户无须更新 CLI 或重新配置摘要。
固定摘要用户在现场内容变化后会因旧摘要不匹配而拒绝运行；如需改用当前模式，执行
`fe-cli configure-run`。原有自定义路径、节点、环境和时限须在命令中显式保留，
否则将保存标准默认值。旧固定请求仍保留原摘要；已有结果与本机回执继续保留。
固定目录模式不承诺现场可直接重跑任意旧版本；历史工件及实验目录的清理由维护者另行确认。
本节说明配置与更新约定，不代表客户端自动部署、自动停机或自动升级服务器。

旧配置和已保存结果保持只读兼容，旧上传运行代码模式不再支持。
仅含旧解释器路径的 legacy 配置不会被 init 自动补成当前模式，准备新任务会拒绝，
须显式迁移，详见[迁移说明](core_transition.md)。
操作和结果合同见[单因子运行说明](single_run.md)。

## 使用边界

服务器登录权限、数据使用权限和计算资源分配须分别获准。
配置成功或模拟流程通过不能证明真实执行、数据口径或历史 PIT 已验收。
公开客户端发布不代表服务器已部署；标准路径是客户端配置默认值，
不是服务器已就绪或已授权的证据。本页不提供服务器地址或部署步骤。
