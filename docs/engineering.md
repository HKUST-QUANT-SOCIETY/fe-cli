# fe-cli engineering

本文件保存随仓库提交的工程规则；根 `AGENTS.md` 为本机入口，不纳入版本控制。
本机协作规则继承工作区指导；环境与权限遵循使用者设置。
版本、组件边界、迭代记录、安装及发布遵循 [Core/CLI 共享维护工作流](shared_release_workflow.md)。
日常变更先登记根 `CHANGELOG.md` 的 Unreleased，检查点提交与正式发布分开。

- 使用 `uv sync --locked`、`uv run fe`；Python >=3.12，客户端依赖保持轻量。
- 当前支持本地模拟、用户显式选择的在线查询与单因子真实运行；默认仍为模拟模式。
- 普通查询只允许 `cluster-envs`、`cluster-status`、`cluster-history`；单次运行通过独立的
  `cluster-submit` 和 `cluster-results` 传输入口。禁止隐式连接和任意远程命令。
  显式 `--online run` 或在线 RunEditor 中按 Enter 确认才提交；`results` / `collect` 才下载并校验落值。
- 服务器更新必须先推送并发布 Core，再由服务器从远端拉取指定发布版本；禁止直接修改服务器源码或上传本地源码补丁。
- 服务器写入、安装和测试作业需用户明确授权；日常应用的真实提交由使用者显式触发。
  本库只交付客户端，不提供服务器部署器或后端实现。
  在线取消不支持，服务器安装继续由维护者处理；增量、run all 不在本次范围。
- `/status`（兼容 `/setup`）只建立独立 SSH 握手检查连接和公钥认证，不执行远程命令、不读取环境列表；
  只在确认认证成功后展示认证公钥指纹，不从本机密钥存在或候选密钥推断成功。
- 默认资源为 `quant-a`、6 CPU、18G；`/node` 选择 A/C，`/resources` 按 1 CPU + 3G 成对递增。
  A 上限 6 CPU / 18G，C 按普通作业上限提供 8 CPU / 24G；运行配置冻结到单个任务。
  不在客户端安装 Factor Engine 或数据访问依赖。
- `/range` 与普通 CLI `range` 保存用户级默认日期，DateRangeStore 默认使用本机 range.json；
  `--range-config` 可隔离。run/prepare 仅继承未覆盖的日期端点，单次覆盖及已有任务不得回写默认值。
  日期必须是真实 ISO 日期且 start <= end；损坏配置保留。范围编辑使用内联 DateRangeEditor。
- `src/fe_cli/backend.py` 负责模拟状态和本地持久化；界面与普通 CLI 共用该接口。
- `config.py` 只保存本地连接参数；`remote.py` 通过原生 OpenSSH 执行白名单只读查询。
  不读取私钥正文，不关闭主机校验，不经过本地 shell 拼接命令，不将模拟结果混为在线结果。
- `workspace.py` 的 init 显式创建用户本机工作目录；`catalog.py` 管理标准 CSV 因子定义，
  初始化和增删改均不得静默覆盖损坏文件或已有内容。`/init`、`/factor` 在在线模式下仍仅操作本机。
  单独保存定义不代表 FE 校验或真实计算成功；增量执行尚未实现。
  `execution.py` 冻结单次请求，`delivery.py` 验证 manifest 与实际 Parquet 后发布不可变结果，
  最终 `runs/REQUEST_ID/commit.json` 是本机可见的提交点，不能用下载成功代替交付成功。
- init 自动补齐标准路径的本机运行配置，重复初始化保留自定义配置；configure-run 可覆盖路径。
  新配置不固定发布 SHA，由作业启动时解析并记录实际 Core 身份；旧固定配置继续严格校验。
  默认 A、research、30 分钟。只上传请求；FE 仅在运行端依赖，本机用 PyArrow 校验结果。
  提交确认丢失保持 unknown，不自动重复提交；同一结果重复导入须幂等，冲突明确拒绝。
- 模拟输出必须明确标记，不得宣称真实 FE、PIT、数据访问或集群验收通过。
- 当前产品界面统一使用英文（菜单、按钮、状态和提示）；项目文档可使用中文。
- 交互启动可后台检查固定公开仓库的 CLI 版本；检查失败不影响使用，提供关闭选项，
  普通命令不得因此联网或改变 JSON 输出。显式 `--update` 才安装并在完成后提示重启，
  不切换服务器 Core，不覆盖其他安装方式，不向更新服务发送因子或 SSH 配置。
- 界面使用近黑底色与克制的柔和语义色；主界面保持单栏，任务按需查询，资源摘要靠近输入框。
- 简单配置选择统一使用 `picker.py` 的 InlinePicker，嵌入命令框上方，不打开独立窗口或遮罩；
  完整任务参数确认使用同一区域的 RunEditor，不弹独立窗口。
- 因子新建/编辑使用 FactorEditor 内联组件，同样嵌在命令框上方；保留多行表达式和失败草稿，
  通过原有 Catalog 校验及并发检查后才关闭。
- RunEditor / FactorEditor 使用 Enter 确认、Ctrl+J 换行、Esc 取消；Enter 在下拉选择器和
  Details 等控件中保留原语义，不得触发提交。任务草稿与因子编辑互斥，提交前的本机校验失败保留草稿。
- F2 在原输出区域切换只读文本选择快照，Ctrl+C / F8 复制选区；不把渲染后的软换行写入原始路径。
  复制使用 Textual 的终端剪贴板接口，提示仅表示请求已发出，不宣称系统剪贴板已更新。
- 共享集成文件：`pyproject.toml`、`uv.lock`、`README.md`、本文件由主代理维护。
- 验证：定点 `uv run pytest -q tests/<file>`；收尾全量一次；`uv run ruff check .`。

## 本地交付与文档同步

- 每个可验收交付检查点形成独立本地 commit，并在交付时报告 hash，无须等待逐次授权。
  提交前审阅并按任务路径暂存，保留其他任务的改动；本地整理不授权推送、PR 或通知他人。
- 每次完成迭代记录，在同一检查点同步根 `README.md` 的“近期迭代”，简述变化、
  用户可见影响与详细记录链接；完整过程留在 `docs/development.md` 或专题文档。
- 修改安装、入口、配置、依赖、持久化或默认行为时，同步 README 正文与示例；
  区分当前可用、历史记录、后续需求及尚未验收的能力，交付前核对本地链接。
- 仅完成当前任务直接必要的改动，复用现有模式；按风险选择验证，验证通过后收口。
- 源码、测试、文档和锁文件纳入版本控制；虚拟环境、缓存、安装包、截图、
  在线查询捕获和本机因子数据继续保留在忽略目录，不为整理而删除。
