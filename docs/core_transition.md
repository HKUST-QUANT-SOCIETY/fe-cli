# 客户端安装与运行配置迁移

CLI 使用独立版本线；受管理起点为 `0.1.0`。此前实验版本的数字排序不能代表
安装迁移方向，切换时应显式选择目标工件并保留 workspace。
安装、升级与回退步骤见[安装手册](installation.md)。

## 当前公开范围

公开仓库和客户端安装包只包含界面、本机因子库与配置、请求和通信合同、
SSH 提交查询、结果校验与本机管理。服务器计算引擎、部署、执行和数据适配实现
不随客户端发布或安装。旧工程历史保留在私有历史中，不并入公开仓库起始历史。

## 0.2.0 源码的默认运行模式

最新正式客户端仍为 `0.1.1`；本节描述源码 `0.2.0`，不代表该版本已发布或服务器已更新。
旧上传运行代码模式已移除。首次 `init` 自动创建本机 `runtime.json`：

- 解释器：`/public/fe-core-env/bin/python`。
- 数据目录：`/srv/quant/data/shared/ashare_lqtp_data`。
- Core 入口：`/public/fe-core`。
- 节点 / 环境 / 时限：`quant-a` / `research` / `00:30:00`。
- `release_sha256: null`：选择作业启动时的当前 Core。

初始化不连接服务器，不证明默认路径可用或已获数据权限；重复初始化不覆盖已有有效配置。
`configure-run` 的路径参数可选，未填写时使用上述标准值；
省略 `--release-sha256` 选择当前模式，指定它则保留高级固定摘要模式。
新任务只上传请求；服务器 runner 必须支持 `--release-sha256 current`，在作业启动时
校验 Core 和清单，将真实摘要、Core 提交和 wheel 身份写入结果 `engine`，不改写原请求。
当前模式下，路径和接口兼容的 Core 更新不要求更新 CLI 或重新配置摘要。
配置示例与结果身份要求见[服务器运行配置](public_runtime.md)。

## 从既有配置迁移

- 已有自定义运行配置保持原值，`init` 不自动转换或覆盖。
- 仅含 `remote_python` 的旧 JSON 保持 legacy 含义，缺少 Core 入口和数据路径；
  `prepare` 会拒绝，须显式运行 `configure-run` 后再创建新请求。
- 已固定 SHA 的配置和请求继续严格固定；服务器原目录更新后，旧摘要不匹配会拒绝运行。
  标准路径用户可执行 `fe-cli configure-run` 改用当前模式。
  自定义路径用户必须同时显式传回自己的 `--remote-python`、`--data-root`、
  `--release-root` 及节点、环境、时限；命令不继承省略项，省略会采用标准默认值。

迁移不改写用户 CSV、已冻结请求或旧结果。裸字段和 `col()` 表达式均按原文提交，
语义由服务器 Core 解释；不为迁移自动改写因子定义。
SSH 状态主入口改为 `/status` 和 `fe-cli --online status`；
`/setup` 和 `setup` 保留兼容别名，仅做握手认证检查，不查询其他远程入口。

## 旧资料与恢复

旧配置和历史结果保留只读兼容；这不表示旧任务能直接重新提交。
旧请求、回执、产物摘要和结果身份不为迁移重写，不自动恢复计算或重复提交。
如需重新计算，应先完成新配置，再创建独立请求，保留旧结果供追溯。

请求/结果协议仍为 `fe-cli-result-v1`，服务清单协议为
`fe-cli-public-release-v1`。协议兼容不等于数值、数据权限或所有节点均已验收。
客户端回退与服务器配置回退分别处理；回退客户端不会改变已提交任务或已有结果。
客户端正式发布状态见[安装手册](installation.md)；不据此宣称服务器已部署或真实计算已验收。
