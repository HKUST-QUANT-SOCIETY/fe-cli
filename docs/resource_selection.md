# 节点与资源选择

资源选择保存下一任务的本机默认请求，不连接服务器或申请算力。
默认选择 A、6 CPU、18 GB；每增加 1 CPU 同时增加 3 GB 内存。

| 节点选择 | CPU 档位 | 对应内存 |
| --- | --- | --- |
| A | 1–6 | 3–18 GB |
| C | 1–8 | 3–24 GB |

这些是客户端允许填写的请求范围，实际资源和服务可用性由获授权的服务器决定。

## 设置默认请求

终端输入 `/node` 或 `/resources`，在命令框上方的内联选择器中修改，
Enter 确认、Esc 取消；也可直接输入：

```text
/node C
/resources 8
```

普通 CLI 对应 `fe-cli node C`、`fe-cli resources 8`；不带参数查看当前值。
偏好保存到本机配置，重启后恢复；全局 `--resource-config PATH` 可隔离配置。

从 C 的高档位切到 A 时，选择器会明确显示降低后的资源。
直接命令切换到 A 而当前 CPU 超过上限会拒绝；先降低 CPU，再切换节点。
损坏配置会报错并保留，不会静默重建。

## 单次覆盖与冻结

`/run` 预填当前默认请求，允许仅修改本次任务。
准备请求后，节点、CPU 和内存固定到该任务；修改默认值不会影响已有任务，
单次覆盖也不改写默认值。在线模式下资源设置仍只操作本机。

运行配置可以限定可用节点；只有维护者确认既有服务可共享运行时，才使用
`configure-run --node shared`。完整配置见[服务器运行配置](public_runtime.md)。
选择节点或资源成功不代表数据权限、实际分配或计算验收通过。
